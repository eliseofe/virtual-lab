# Handover — what changed 24–26 September 2026

Read this if you last worked on the repository before 24 September 2026. Between 24 and 26 September three bodies of work landed: the refactoring plan under #425 (technical debt), the one-grammar authoring language (#575–#577), and an audit of the stored Experiments (#592, #594, #596). Much of what an earlier reading of the code or documents would suggest is no longer true. This page lists what changed and where each rule now lives. It is a map, not an authority: when it disagrees with the documents it points to, they win.

## 1. How work reaches production

- **Pull requests only.** A GitHub ruleset rejects direct pushes to `main` and merges whose `build` check is not green. Documentation-only pull requests still run `build` and publish nothing (outcome **not-a-candidate**). See `DEVELOPMENT_WORKFLOW.md`, "Pull requests only".
- **Follow the exact run.** After a push or merge, watch the one workflow run for that commit (`web/scripts/wait-for-run.mjs <sha> [--pull-request]`), not the Actions history. The possible outcomes are defined in `DEVELOPMENT_WORKFLOW.md`, "Exact-run outcomes".
- **Browser check before publishing.** CI runs the production smoke against the built `dist` before it deploys (`web/scripts/pre-publish-smoke.mjs`; active surfaces in `web/product-surface.json`).
- **Terminal report.** Each release carries `.github/terminal-report.json` (schema `vlab.terminal-report/2`) with the owner-facing outcome and the issue to close.
- **Experiment MCP deployment is manual.** It is done through the Supabase connector (`DEVELOPMENT_WORKFLOW.md`, "Experiment MCP deployment"; `docs/EXPERIMENT_MCP.md`). The deployed function is a small stub that imports `supabase/functions/experiment-mcp/index.ts` from GitHub at a pinned commit. Merging a change to the MCP code does **not** deploy it. The live server is **3.28.0**, pinned to `79d173b`, and publishes contract `vlab.authoring/0.17`.

## 3. How the web app is now organised (#425)

The plan and its findings are in `docs/REFACTORING_AUDIT_2026-09-24.md`.

- **Model-view-controller** (#560–#569). Simulation state lives in `web/src/runtime/runtime-model.js`. Other modules act on the simulator through `runtime/simulation-commands.js`, not by clicking hidden buttons or reading DOM text. Results and authoring have their own adapters (`results-react-adapter.ts`, `authoring-react-adapter.ts`), and one authoring controller has a direct Apply command.
- **Page events.** Remaining coordination between modules uses DOM events with the `vlab:` prefix. Every event is listed in `docs/ARCHITECTURE.md` §19, and `web/tests/page-events.test.mjs` fails if an event is sent without being listed or listened to. Three page-wide `MutationObserver`s remain by design, filtered of live simulation traffic.
- **One database client.** `web/src/supabase-client.js` (configuration in `supabase-config.js`) replaces eight copies of the credentials.
- **Styles are CSS files.** They are in `web/src/*.css` and `web/src/styles/`. JavaScript no longer injects style text.
- **Registry split** (#554). Five tested parts of `registry-ui-v3.js` moved into `web/src/registry/` (`data`, `labels`, `revisions`, `workspace-location`, `workspace-status`); the remaining view code is still in `registry-ui-v3.js`.
- **Simulator core.** The Rust crate is formatted and clippy-clean, with no `include!` files.

Optional leftovers, none started or scheduled: an explicit start-up entry point (audit F4); splitting `crates/kernel/src/lib.rs` (about 1,900 lines; F10.3); further splits of `registry-ui-v3.js` and `experiment-library.js` (F7); splitting the MCP `index.ts` (F12); renaming tests named after issue numbers (F14); small clean-ups (F15). The superseded database functions (F11) belong to security #301 / #302, not to #425.

## 4. The authoring language (D-021, D-022, D-023)

The decisions are in `docs/DECISIONS.md`; the author-facing contract is in `docs/AUTHORING_CONTRACT.md`.

- **One code grammar** (D-021). Initialization, the environment field, the Controller and Metrics share the same statements, operators, types, `if/elif/else`, bounded `for … in range(K)`, `%` and `//`. They differ only in what each may **read and do**, which is enforced by which names each can use. Configuration remains a separate data format. The shared parser is in `web/src/authoring-core/`.
- **Anonymous robots** (D-022). A Controller never sees `N`, `ARENA_SIZE`, `EXPERIMENT_DURATION`, its own index or other robots' indices. It knows only its sensors, its own memory, its constants and its own random stream.
- **Heterogeneity through groups** (D-023; guide `docs/HETEROGENEITY_GUIDE.md`). Initialization declares `group(...)` / `rest_of_group(...)` with a `dimension=` and optional `within=` for nested splits. Groups receive starting memory (`set_state`), reference sensors (`equip`) and read-only traits (`set_trait`), which a Controller reads as `NAME = trait(default)`.
- **Retired forms** are rejected with a message naming the replacement:
  - `set_agent_state` and `role(...)` → groups plus `set_trait` (read-only) or `set_state` (starting memory);
  - per-robot `set_agent_reference_sensor(...)` → `equip`;
  - `rest=True` → `rest_of_group(...)`.
- **Environment field.** It accepts statements: local variables, `+=`, and `if/elif/else` with a return on every path.
- **Contract version** is now `vlab.authoring/0.17`. Any language change must, in the same ticket, update the web compilers, the vendored MCP copies (sync script), the published contract and the equivalence corpus, and then redeploy the MCP.
